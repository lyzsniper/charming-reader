# 检索策略深度参考

## 前言

本文档汇总了学术界和工业界最新的检索策略和技术，作为 RAG Enhancement 技能的深度参考资料。

## 1. 查询优化技术

### 1.1 HyDE (Hypothetical Document Embeddings)

**论文**：Precise Zero-Shot Dense Retrieval without Relevance Labels (Gao et al., 2022)

**核心思想**：
- 传统方法：用查询 q 的 embedding 检索
- HyDE：让 LLM 生成假设答案 d，用 d 的 embedding 检索
- 原理：假设答案与真实文档在嵌入空间中更接近

**实现**：
```
Query: "What are the benefits of transformer architecture?"

Hypothetical Answer (generated by LLM):
"Transformer architecture offers several key benefits including parallel 
processing capabilities, ability to capture long-range dependencies through 
self-attention mechanism, scalability to large datasets, and superior 
performance on various NLP tasks..."

Use embedding of hypothetical answer for retrieval
```

**适用场景**：
- 复杂的概念性查询
- 用户查询表达不够学术化
- 语义检索优先

**局限**：
- 需要额外 LLM 调用（增加延迟）
- 假设答案可能偏离用户真实意图

### 1.2 Query Expansion with LLM

**多角度查询生成**：
```
Original Query: "deep learning optimization"

LLM-generated variants:
1. "optimization techniques for training deep neural networks"
2. "gradient descent and variants in deep learning"
3. "hyperparameter tuning in deep learning models"
4. "convergence and stability in neural network training"

Retrieve for each variant, merge results
```

**同义词和相关词扩展**：
```
Query: "neural network"
Expand: "neural network" OR "artificial neural network" OR "ANN" 
        OR "deep learning model" OR "deep neural network" OR "DNN"
```

### 1.3 Query Decomposition

**复杂查询分解**：
```
Complex Query: 
"Compare the performance of BERT and GPT on text classification and 
question answering tasks"

Decompose into:
Sub-query 1: "BERT performance text classification"
Sub-query 2: "BERT performance question answering"
Sub-query 3: "GPT performance text classification"
Sub-query 4: "GPT performance question answering"
Sub-query 5: "BERT vs GPT comparison"

Retrieve for each sub-query, synthesize results
```

## 2. 混合检索策略

### 2.1 Reciprocal Rank Fusion (RRF)

**论文**：Reciprocal Rank Fusion outperforms Condorcet and individual Rank 
Learning Methods (Cormack et al., 2009)

**公式**：
```
RRF_score(d) = Σ 1 / (k + rank_i(d))

其中：
- d: document
- rank_i(d): document d 在第 i 个排序列表中的排名
- k: 常数（通常为60）
```

**示例**：
```
Dense retrieval results:
Doc A: rank 1
Doc B: rank 3
Doc C: rank 5

Sparse retrieval (BM25) results:
Doc A: rank 2
Doc B: rank 1
Doc C: rank 10

RRF scores:
Doc A: 1/(60+1) + 1/(60+2) ≈ 0.0325
Doc B: 1/(60+3) + 1/(60+1) ≈ 0.0323
Doc C: 1/(60+5) + 1/(60+10) ≈ 0.0297

Final ranking: A > B > C
```

**优势**：
- 简单有效
- 不需要训练
- 对不同排序方法的scale差异鲁棒

### 2.2 Weighted Combination

**线性组合**：
```
final_score = α * dense_score + (1-α) * sparse_score

其中 α 可根据任务调整：
- 语义查询：α = 0.7-0.8
- 关键词查询：α = 0.3-0.4
- 平衡查询：α = 0.5-0.6
```

**动态权重**：
```
根据查询特征动态调整权重：
- 如果查询包含专业术语 → 提高sparse权重
- 如果查询是自然语言问题 → 提高dense权重
- 如果查询很短（<5 words）→ 提高sparse权重
```

### 2.3 Multi-Stage Retrieval

**三阶段检索**：
```
Stage 1: Fast Candidate Generation (BM25)
- 从整个语料库快速筛选 top 1000 candidates

Stage 2: Dense Re-ranking (Bi-encoder)
- 用 dense retrieval 重排 top 1000 → top 100

Stage 3: Cross-encoder Re-ranking
- 用 cross-encoder 精排 top 100 → top 10

Final: Use top 10 as context
```

**性能权衡**：
- Stage 1: 速度快，召回率高，精确度低
- Stage 2: 速度中等，召回率中等，精确度中等
- Stage 3: 速度慢，召回率低，精确度高

## 3. 先进的检索模型

### 3.1 ColBERT (Contextualized Late Interaction)

**论文**：ColBERT: Efficient and Effective Passage Search via Contextualized 
Late Interaction over BERT (Khattab & Zaharia, 2020)

**核心思想**：
- 预计算文档的 token-level embeddings
- 查询时计算 query-document token 交互
- 比 cross-encoder 快，比 bi-encoder 准

**MaxSim操作**：
```
For each query token q_i:
    Find max similarity with all document tokens
    sim(q_i, D) = max_{j} (q_i · d_j)

Overall score: Σ_i sim(q_i, D)
```

**优势**：
- 保留细粒度交互
- 可预计算文档表示（加速检索）
- 性能接近cross-encoder

### 3.2 Dense Passage Retrieval (DPR)

**论文**：Dense Passage Retrieval for Open-Domain Question Answering 
(Karpukhin et al., 2020)

**训练策略**：
```
Positive pairs: (question, relevant passage)
Hard negatives: (question, high-BM25 but irrelevant passage)

Loss: Contrastive learning
goal: maximize similarity between q and p+
      minimize similarity between q and p-
```

**使用**：
```
Encode query: q_emb = query_encoder(query)
Encode docs: d_emb = doc_encoder(doc)
Similarity: score = cosine_similarity(q_emb, d_emb)
```

### 3.3 SPLADE (Sparse Lexical and Expansion)

**论文**：SPLADE: Sparse Lexical and Expansion Model for First Stage Ranking 
(Formal et al., 2021)

**核心思想**：
- 结合 dense 和 sparse 的优势
- 使用 BERT 生成稀疏表示（类似BM25）
- 但是语义感知的稀疏表示

**特点**：
- 可解释性好（可以看到哪些词被激活）
- 效率高（稀疏表示，快速检索）
- 性能强（结合语义理解）

## 4. 重排序技术

### 4.1 Cross-Encoder Architecture

**模型**：
```
Input: [CLS] query [SEP] document [SEP]
       ↓
    BERT/RoBERTa
       ↓
    [CLS] representation
       ↓
    Linear layer
       ↓
    Relevance score
```

**使用流程**：
```
1. Bi-encoder retrieval: 从10M文档中选出top 100
   时间：~100ms

2. Cross-encoder reranking: 对100个文档精排
   时间：~1s (100 × 10ms per doc)

3. 返回 top 10

总时间：~1.1s
```

**模型选择**：
- `cross-encoder/ms-marco-MiniLM-L-6-v2`：快速，性能中等
- `cross-encoder/ms-marco-electra-base`：平衡
- `cross-encoder/qnli-electra-base`：高质量，较慢

### 4.2 Listwise Reranking

**Pointwise**（传统）：
- 独立为每个文档打分
- 不考虑文档间关系

**Pairwise**：
- 比较文档对
- 学习相对排序

**Listwise**（最优）：
- 同时考虑整个候选列表
- 优化整体排序质量
- 模型：RankNet, LambdaMART, ListMLE

### 4.3 Diversification

**问题**：Top-K 结果可能高度重复

**解决**：MMR (Maximal Marginal Relevance)
```
Score(d) = λ × Relevance(d, query) 
           - (1-λ) × max Similarity(d, already_selected)

选择过程：
1. 选择最相关的文档 d1
2. 下一个文档：既相关又与d1不同
3. 继续选择，平衡相关性和多样性

参数：λ = 0.5-0.7（平衡相关性和多样性）
```

## 5. 上下文管理

### 5.1 Lost in the Middle

**问题**：研究发现 LLM 对上下文中间部分的信息利用率低

**论文**：Lost in the Middle: How Language Models Use Long Contexts 
(Liu et al., 2023)

**发现**：
- 最重要的信息放在开头或结尾
- 中间的信息容易被"忽视"

**策略**：
```
将最相关的chunks放在开头和结尾：

Context = [
    chunk_1 (最相关),
    chunk_3 (第三相关),
    chunk_5 (第五相关),
    ...
    chunk_4 (第四相关),
    chunk_2 (第二相关)
]

即：1, 3, 5, ..., 4, 2 的顺序
```

### 5.2 Context Compression

**LongLLMLingua**：
```
原始上下文：1000 tokens
压缩后：300 tokens (保留关键信息)

方法：
1. 识别关键句子（与查询最相关）
2. 移除冗余句子
3. 保留连贯性
```

**Selective Context**：
```
对上下文中的每个句子评分：
relevance_score = similarity(sentence, query)

保留高分句子，移除低分句子
```

### 5.3 Context Window Optimization

**Sliding Window**：
```
如果文档很长：
- 不要取单个大chunk
- 使用滑动窗口：多个重叠的小chunks

示例：
Doc (3000 tokens) → 
    chunk 0: tokens 0-500 (overlap 100)
    chunk 1: tokens 400-900
    chunk 2: tokens 800-1300
    ...
```

**Hierarchical Retrieval**：
```
Level 1: 检索相关文档（粗粒度）
Level 2: 在相关文档内检索相关段落（细粒度）

提高精确度
```

## 6. 学术特定策略

### 6.1 Citation-Aware Retrieval

**引用图增强**：
```
检索到论文 A 后：
1. 提取 A 引用的论文列表 (references)
2. 提取引用 A 的论文列表 (citations)
3. 这些论文也加入候选集

逻辑：
- A引用的论文：相关背景
- 引用A的论文：后续发展
```

**Co-citation Analysis**：
```
如果论文 B 和论文 C 都被论文 A 引用：
→ B 和 C 可能相关

可用于发现相关但未直接检索到的论文
```

### 6.2 Section-Aware Retrieval

**训练阶段**：
```
为不同章节训练专门的检索器：
- intro_retriever: 专门检索 Introduction
- method_retriever: 专门检索 Methods
- result_retriever: 专门检索 Results
```

**检索阶段**：
```
根据查询类型选择检索器：
if "how to" in query:
    use method_retriever
elif "performance" in query:
    use result_retriever
elif "background" in query:
    use intro_retriever
```

### 6.3 Temporal Weighting

**时间衰减**：
```
对于"state-of-the-art"查询：
weight = base_score × (1 + 0.1 × (year - 2015) / 10)
更新的论文权重更高
```

**时间分段**：
```
对于"research evolution"查询：
将结果按时间分组：
- Early work (before 2015)
- Middle period (2015-2020)
- Recent advances (2020-present)
```

## 7. 评估指标

### 7.1 Retrieval Metrics

**Recall@K**：
```
Recall@K = (相关文档在Top-K中的数量) / (总相关文档数量)

示例：
10个相关文档，Top-10中包含6个
Recall@10 = 6/10 = 0.6
```

**Precision@K**：
```
Precision@K = (Top-K中相关文档数量) / K

示例：
Top-10中6个相关，4个不相关
Precision@10 = 6/10 = 0.6
```

**MRR (Mean Reciprocal Rank)**：
```
RR = 1 / (第一个相关结果的排名)

示例：
查询1：第一个相关结果在位置2 → RR = 1/2
查询2：第一个相关结果在位置1 → RR = 1/1
查询3：第一个相关结果在位置5 → RR = 1/5

MRR = (1/2 + 1/1 + 1/5) / 3 ≈ 0.567
```

**NDCG (Normalized Discounted Cumulative Gain)**：
```
DCG@K = Σ (rel_i / log2(i+1))

考虑相关性程度（0-3分）和位置
```

### 7.2 End-to-End Metrics

**Faithfulness**：
```
答案中的事实是否都能在检索内容中找到？

检测方法：
1. 提取答案中的事实陈述
2. 检查每个事实是否在检索chunk中
3. Faithfulness = 可验证事实 / 总事实
```

**Answer Relevance**：
```
答案是否回答了问题？

检测方法：
LLM评分："The answer addresses the question. Score: [1-5]"
```

**Context Precision**：
```
检索到的chunks中，有多少是真正有用的？

Context Precision = 有用chunks / 总chunks
```

## 8. 实用建议

### 8.1 选择策略的原则

**数据量小（<1000文档）**：
- 使用简单的dense retrieval
- 不需要复杂优化

**数据量中（1000-100K文档）**：
- Dense retrieval + BM25 混合
- 考虑使用重排序

**数据量大（>100K文档）**：
- 多阶段检索（BM25 → Dense → Cross-encoder）
- 投资训练domain-specific检索模型

### 8.2 延迟优化

**优先级**：
```
1. 用户体验 > 绝对精确度
2. 95th percentile latency < 2s
3. 如果超时，返回部分结果优于等待

策略：
- 设置retrieval timeout（如500ms）
- 并行执行多个检索策略
- 使用缓存热门查询
```

### 8.3 成本优化

**检索成本**：
- 预计算文档embeddings（一次性成本）
- 使用量化降低存储和计算成本
- 使用更小的embedding模型（如384维vs768维）

**生成成本**：
- 压缩上下文降低input tokens
- 使用更小的生成模型处理简单查询
- 缓存常见问题答案

## 9. 前沿研究方向

### 9.1 Self-RAG

**论文**：Self-RAG: Learning to Retrieve, Generate and Critique (Asai et al., 2023)

**核心**：让LLM自主决定何时检索、检索什么、如何使用检索结果

### 9.2 REPLUG

**论文**：REPLUG: Retrieval-Augmented Black-Box Language Models (Shi et al., 2023)

**核心**：将检索结果作为LLM的"插件"，增强黑盒模型能力

### 9.3 Dense X Retrieval

**研究方向**：不仅检索文本，还检索表格、图像、代码等多模态内容

### 9.4 Learned Sparse Retrieval

**代表**：SPLADE, uniCOIL

**趋势**：结合neural和sparse的优势，同时保持效率和可解释性
