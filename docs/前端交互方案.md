**“流式学术空间 (Streamlined Academic Workspace)”** 前端设计方案。

---

### 一、 核心设计哲学：Canvas & Transparency

1. **Chat First (对话即入口):** 没有任何 Dashboard，首页就是输入框。
2. **Split Context (双屏语境):** 这是一个学术工具，必须坚持 **“左脑对话（Chat），右脑原文（PDF）”** 的并列布局。
3. **Glass Box (透明盒子):** AI 不是黑盒。检索、思考、分片的过程必须像 RAGFlow 或 DeepSeek 一样可视化，增加学术严谨性。

---

### 二、 页面流转与布局方案

#### 1. 首页：Zero State (零态启动页)

*参考对象：Gemini, ChatGPT, v0*

这是用户进入后的第一眼。没有任何多余的干扰。

* **布局：** 页面中央垂直居中。
* **核心元素：**
* **超大输入框 (Omnibox):** 位于屏幕中央偏下位置（留出上方展示 Logo 和 Slogan）。
* **多模态输入区：** 输入框内左侧是回形针图标（上传 PDF/图片），右侧是发送键。支持**直接拖拽 PDF 到整个页面**。
* **快捷指令丸 (Prompt Pills):** 输入框上方漂浮几个半透明胶囊按钮，例如：“上传论文并总结创新点”、“搜索知识库中的 Transformer 变体”。
* **侧边栏 (Sidebar):** 极度收敛。默认只显示图标（历史记录、知识库、设置）。鼠标悬停才展开。



#### 2. 工作台：Active Workspace (沉浸式阅读与对话)

*参考对象：Dify (工作流编排感的简化), Cursor (代码编辑器的分栏感)*

一旦用户发送消息或上传文件，中央输入框上移，页面切换为 **“双栏协作模式”**。

* **左侧：智能交互流 (Chat Stream) - 占宽 40%**
* **流式卡片 (Streaming Cards):**
* **User:** 简洁气泡。
* **Agent (思考态):** 这是一个动态变化的 **“折叠面板”**（参考 o1 或 DeepSeek）。
* *初始态：* 显示脉冲动画 + 实时状态文字（“正在解析 PDF 结构...”、“正在从知识库《深度学习.pdf》中检索...”）。
* *完成态：* 自动折叠为一个“思考过程”胶囊，点击可展开查看详细的检索路径（Retrieved Chunks）和推理逻辑。


* **Agent (输出态):** 标准 Markdown 渲染。**关键点：** 所有的引用必须带角标 `[1]` 或高亮链接。


* **底部常驻输入框：** 悬浮在底部，不随对话滚动。


* **右侧：原文/知识映演区 (Context Canvas) - 占宽 60%**
* **场景 A：查看 PDF**
* **原生渲染：** 类似浏览器自带的 PDF 查看器，但增加了“图层”。
* **高亮联动：** 当左侧 AI 回答“根据第 3 页的公式...[2]”，点击 `[2]`，右侧 PDF 自动滚动并高亮对应段落。
* **划词交互：** 在 PDF 上选中文本，浮现 "Ask AI" 按钮，点击后将该段落作为 Context 填入左侧输入框。


* **场景 B：查看引用源 (Source Viewer)**
* 如果问题是基于知识库回答的，右侧不显示 PDF，而是显示 **“检索命中切片墙”**。
* 展示 AI 到底参考了哪几段话生成的答案（参考 RAGFlow 的命中结果展示），方便用户核对事实。





#### 3. 知识库：Knowledge Manager (扁平化资产管理)

*参考对象：Coze (知识库管理), RAGFlow (分片可视化)*

不需要复杂的菜单，它就是一个**模态窗口 (Modal)** 或者一个 **全屏覆盖层 (Overlay)**，从侧边栏点击进入。

* **布局逻辑：** 类似 macOS Finder 或 Notion 的列表视图。
* **一级视图：数据集列表**
* 卡片式展示：图标（PDF/Word）+ 名称 + 状态（已索引/索引中）+ 上传时间。
* **拖拽上传区：** 顶部有一个明显的虚线框区域，支持批量拖入文件。


* **二级视图：分片显微镜 (Chunk Microscope) —— 你的核心需求**
* 点击某个文件进入详情。
* **左侧：原文预览。**
* **右侧：分片结果流 (Chunk Stream)。**
* 视觉上像一条条被切开的“纸条”。
* **可视化元数据：** 每个纸条上标注 `Chunk ID`, `Token Count`。
* **搜索验证栏：** 顶部有个搜索框“测试召回效果”。输入问题，下方的“纸条”会根据相似度重新排序并高亮，让你直观看到 RAG 的效果。





---

### 三、 关键交互细节 (Micro-Interactions)

为了体现“现代感”，交互必须细腻：

1. **上传的即时反馈：**
* 拖入 PDF 时，文件不要只是出现在列表里。在输入框上方应该出现一个 **“解析进度条”**，伴随微小的动画（像扫描仪的光效），暗示系统正在“阅读”和“分词”。


2. **引用溯源 (The "Magic Jump"):**
* 这是学术产品的灵魂。当鼠标悬停在 AI 回答的 `[引用]` 上时，显示一个小浮窗预览原文片段；点击时，右侧 PDF 视图**平滑滚动**到位置，并显示一个**淡入淡出的黄色高亮**背景。


3. **思维链的呼吸感：**
* 在 AI 生成答案之前，不要只展示 Loading。展示“正在阅读 Section 3...”、“正在对比实验数据...”。这能极大地缓解用户的等待焦虑，并增加专业感。



---

### 四、 视觉风格建议 (Visual Style)

* **配色 (Color Palette):**
* **背景：** 纯白 (White) 或 极浅灰 (Off-white) —— 模仿纸张的质感。
* **主色调：** 像 Coze 或 Vercel 一样的 **黑白灰主导**，辅以一种 **“科技蓝”** 或 **“深紫”** 作为高亮色（用于引用链接和按钮）。


* **字体 (Typography):**
* 界面 UI 使用无衬线字体 (Inter, San Francisco) 保持现代感。
* **论文内容/Markdown 渲染** 建议引入衬线字体 (Merriweather, Noto Serif)，营造学术阅读的严肃感和舒适度。



### 五、 总结：用户旅程

1. **打开网页** -> 极简大输入框 -> **拖入 PDF**。
2. 系统显示“正在阅读...”，随后**自动分屏**，左侧出欢迎语，右侧展示 PDF。
3. **用户提问**：“这篇文章的核心贡献是什么？”
4. **左侧流式输出**：先显示“思考中：检索摘要章节...”，然后打字机输出总结，文末带有 `[Page 1]` 链接。
5. **用户点击链接** -> 右侧 PDF 自动跳转至第一页摘要处并高亮。
6. **用户点击侧边栏“知识库”图标** -> 弹层划出，用户查看刚刚上传的文件被切分成了哪些段落，确认无误后关闭，继续对话。
