# 修复向量维度不匹配问题

## 问题

```json
{
  "detail": "BadRequestError(400, 'search_phase_execution_exception', 'failed to create query: the query vector has a different dimension [1536] than the index vectors [1024]')"
}
```

## 原因

- **当前查询向量**: 1536 维（使用 text-embedding-v1）
- **索引中的向量**: 1024 维（旧数据）

Qwen 的 embedding 模型维度：
- `text-embedding-v1`: **1536 维**
- `text-embedding-v4`: **1536 维**  
- `text-embedding-v3`: **1536 维**

## 解决方案

统一使用 **1536 维** embedding 模型，重置索引和数据。

## 操作步骤

### 步骤 1: 运行数据库迁移

更新 PostgreSQL 中的向量维度：

```bash
cd backend
alembic upgrade head
```

预期输出：
```
INFO  [alembic.runtime.migration] Running upgrade 5 -> 6, update embedding dimension to 1536
✓ 向量维度已更新为 1536
⚠️  所有旧的 chunks 已删除，需要重新索引文档
```

### 步骤 2: 重置 Elasticsearch 索引

删除旧索引，创建新的 1536 维索引：

```bash
cd backend
python scripts/reset_elasticsearch_index.py
```

预期输出：
```
删除旧索引: paper_index
✓ 旧索引已删除
创建新索引: paper_index (1536 维)
✓ 新索引创建成功（1536 维）
✓ 验证成功：向量维度 = 1536

============================================================
索引重置完成！
============================================================

下一步：重新上传并索引所有文档
```

### 步骤 3: 重启服务

```bash
cd backend
python -m uvicorn app.main:app --reload
```

### 步骤 4: 重新上传文档

由于所有旧数据已被清除，需要重新上传文档：

#### 方法 1: 通过 API 上传

```bash
# 上传文档到知识库
curl -X POST http://localhost:8000/api/upload \
  -F "file=@your_paper.pdf" \
  -F "knowledge_base_ids=YOUR_KB_ID"
```

#### 方法 2: 通过前端上传

1. 访问前端界面
2. 进入"知识库管理"
3. 选择知识库
4. 上传 PDF 文档

### 步骤 5: 验证

测试 RAG 搜索：

```bash
curl -X POST http://localhost:8000/api/rag/search \
  -H "Content-Type: application/json" \
  -d '{
    "query": "Transformer",
    "top_k": 5
  }'
```

应该成功返回结果，不再报维度错误。

## 技术细节

### 为什么会出现维度不匹配？

1. **之前的配置**：使用了 1024 维的 embedding 模型（可能是旧版本或量化版本）
2. **当前的配置**：使用 `text-embedding-v1`（1536 维）
3. **结果**：查询时生成 1536 维向量，但索引中存储的是 1024 维向量

### Qwen Embedding 模型对比

| 模型 | 维度 | 性能 | 推荐 |
|------|------|------|------|
| text-embedding-v1 | 1536 | 基础 | ✅ |
| text-embedding-v4 | 1536 | 改进 | ✅ |
| text-embedding-v3 | 1536 | 最新 | ✅ |

所有模型都是 **1536 维**，性能逐代提升。

### PostgreSQL Vector 维度

```python
# models/sql.py
embedding = Column(Vector(1536))  # 统一为 1536 维
```

### Elasticsearch Mapping

```python
{
    "mappings": {
        "properties": {
            "embedding": {
                "type": "dense_vector",
                "dims": 1536,  # 统一为 1536 维
                "index": True,
                "similarity": "cosine"
            }
        }
    }
}
```

## 配置检查清单

确保以下配置统一：

- ✅ `models/sql.py`: `Vector(1536)`
- ✅ `rag/ingestion.py`: `text-embedding-v1` (1536维)
- ✅ Elasticsearch mapping: `dims: 1536`
- ✅ 所有文档重新索引

## 避免未来出现此问题

### 1. 固定 Embedding 模型

在 `core/config.py` 中明确指定：

```python
EMBEDDING_MODEL: str = "text-embedding-v1"  # 固定使用 v1
```

### 2. 版本管理

如果需要更换 embedding 模型：
1. 创建新的知识库
2. 使用新模型索引文档
3. 逐步迁移数据

### 3. 监控维度

在上传文档时验证维度：

```python
assert len(embedding) == 1536, f"Embedding 维度错误: {len(embedding)}"
```

## 常见问题

### Q1: 可以只更新部分数据吗？

**A**: 不行。向量维度必须统一，所有数据都需要重新索引。

### Q2: 数据会丢失吗？

**A**: 
- **文档元数据**：不会丢失（存储在 MinIO 和 PostgreSQL）
- **向量索引**：需要重新生成（自动处理）

### Q3: 重新索引需要多久？

**A**: 取决于文档数量：
- 10 个文档：约 1-2 分钟
- 100 个文档：约 10-20 分钟
- 1000 个文档：约 2-3 小时

### Q4: 可以使用 1024 维模型吗？

**A**: 不推荐。Qwen 官方模型都是 1536 维，1024 维可能是旧版本。

通过以下步骤解决向量维度不匹配：

3. ✅ 重启服务
